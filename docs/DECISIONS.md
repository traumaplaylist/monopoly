# Журнал решений

Решения принимались автономно. Формат: **решение** — причина.

## Продукт и юридическое
- **Название — «Орбитальный капитал», тема — колонизация Солнечной системы.** Никаких названий, текстов карточек, оформления и фигурок оригинала. Клетки — колонии, купола, станции; дома — «модули», отели — «станции»; тюрьма — «Карантин», «Отправляйтесь в тюрьму» — «Санконтроль», бесплатная стоянка — «Дрейф»; колоды — «Сигнал» и «Совет колонии». Все 32 текста карточек написаны с нуля.
- **Механики и порядок цен/аренд близки к классике.** Механики не охраняются; цифры аренды — это баланс, который проверен десятилетиями. Таблицы набраны заново и местами отличаются.
- **Валюта — «₡» (кредиты).**
- **Язык интерфейса — русский**, тексты событий генерируются из структурированных событий движка (`src/ui/format.ts`), поэтому локализация добавляется без правки ядра.

## Архитектура
- **`src/engine` — чистая детерминированная функция `applyAction(state, action) → {state, events}`.** Без React/Three/DOM. Внутри — `structuredClone` и мутация копии; исходное состояние не меняется (есть тест).
- **ГСЧ mulberry32, его состояние — поле `rng` в `GameState`.** Seed передаётся в `createGame`, дальше генератор «едет» вместе с состоянием. Это даёт: реплей по списку действий, одинаковый результат на клиенте и сервере, сохранение/загрузку без потери случайности. Минус: клиент, у которого есть состояние, может предсказать бросок. Для онлайна сервер (Colyseus) будет отдавать клиентам состояние без поля `rng` — ядро от этого не меняется.
- **Валидация только в движке.** UI решает, активна ли кнопка, через `validate()` (пробный `applyAction`). Отдельных «canX» в UI нет — нет расхождений между интерфейсом и правилами.
- **`getActor(state)` — кто должен действовать сейчас** (текущий игрок, участник аукциона, должник, адресат сделки). На нём строятся и бот-раннер, и будущая серверная проверка «чей ход».
- **Движок возвращает структурированные события** (`moved`, `money`, `card`…). UI строит из них журнал, анимации фишек и показ карточек. Последние 120 событий хранятся в состоянии (журнал после загрузки сохранения).
- **Боты (`src/bots`) — чистая функция `chooseBotAction(state, id) → Action`**, используют тот же `validate`/`applyAction`, что и человек. На сервере их можно запускать без изменений.
- **`GameClient` (`src/game/client.ts`)** — интерфейс `getState/dispatch/subscribe`. Сейчас `LocalGameClient`; для онлайна пишется сетевая реализация, UI не меняется.
- **Состояние UI — Zustand** (`src/game/store.ts`): партия, выбранная клетка, очереди анимаций, показанная карточка.
- **Сохранение — `localStorage`** (работает в Capacitor WebView). Автосохранение после каждого действия, «Продолжить» на стартовом экране.

## Правила (уточнения и упрощения v1)
- **Аукцион:** запускается, если игрок отказался от покупки. Участвуют все активные игроки (включая отказавшегося), ставки по кругу, каждая ставка — любое целое больше текущей (в UI быстрые +1/+10/+50/+100). Лидер ставок пропускается в круге. Пас — окончательный выход. Никто не поставил — клетка остаётся у банка.
- **Долги:** если денег не хватает, создаётся долг (очередь `debts`), игра переходит в фазу `debt`. Должник продаёт постройки/закладывает клетки и платит, либо объявляет банкротство. Карточки «заплатите каждому»/«каждый платит вам» создают несколько долгов, они разбираются по очереди. Наличные никогда не уходят в минус (инвариант проверяется в симуляции).
- **Банкротство перед игроком:** постройки продаются банку за полцены, всё имущество (заложенное остаётся заложенным, без 10% сбора), деньги и карты выхода переходят кредитору. **Перед банком:** клетки возвращаются банку свободными и незаложенными (без аукциона — упрощение v1).
- **Управление имуществом** (строить, продавать, закладывать, выкупать) — только в свой ход (фазы «бросок», «покупка», «конец хода»), а должнику — продажа и залог в фазе долга. В классике это можно делать в любой момент, но для онлайна и ботов детерминированная очередь проще и честнее.
- **Строительство:** только при всей группе, без заложенных клеток в группе, равномерно (на клетке с минимумом), в банке 32 модуля и 12 станций. Станция возвращает 4 модуля в банк. При продаже станции, если модулей в банке меньше 4, клетка получает сколько есть, остальное оплачивается.
- **Аренда:** без построек удваивается при всей группе (заложенные клетки группы не мешают удвоению). Заложенная клетка аренды не приносит.
- **Карантин:** выход дублем (без дополнительного броска), штрафом 50 или картой до броска. После третьей неудачной попытки — обязательный штраф и ход на выпавшее число.
- **Три дубля подряд** — в карантин, ход заканчивается.
- **Карточка «к ближайшей энергостанции»** берёт 10× текущую сумму кубиков (без повторного броска) — меньше случайностей, проще воспроизвести.
- **Сделки:** предлагает только игрок, чей ход, не более 3 предложений за ход (защита от спама). Можно передавать деньги, клетки без построек в группе (заложенные — как есть) и карты выхода. Пока сделка ожидает ответа, ход заморожен.
- **Лимит ходов (опция):** по достижении побеждает максимальный чистый капитал (наличные + цена клеток − залог + стоимость построек). По умолчанию выключен.
- **Бонус за «Старт» — 200**, за проход и за попадание.

## Боты
- **Эвристики, а не дерево поиска.** Резерв наличных зависит от самой опасной аренды на поле. Ценность клетки — изменение «оценки активов» (группы, транспорт) плюс защитная ценность (блок монополии соперника).
- **Торговля:** бот пытается докупить клетки группы у одного владельца, предлагая доплату, рассчитанную по той же модели, по которой он сам принимает сделки (минимальная выгода 25 и не меньше 35% от выгоды партнёра). Подсластитель — клетка, которой не хватает партнёру. Предложения — раз в три круга.
- Первая версия без торговли боты зависали в «пате» (никто не собирал группы, 600 ходов без банкротств). После добавления торговли все 30 симулированных партий на 2–6 ботов заканчиваются банкротством за 60–310 ходов.

## Рендер
- **Поле — одна canvas-текстура 2048², нарисованная в рантайме.** Без загрузки шрифтов (drei `<Text>` тянет шрифт по сети и плохо дружит с офлайном/WebView), корректная кириллица системным шрифтом, один draw call на всё поле — дёшево для телефонов.
- **Фишки — собственные примитивы** (ракета, спутник, кристалл, дрон, модуль, комета).
- **Камера подстраивает дистанцию под соотношение сторон**, OrbitControls без панорамирования, с ограничениями угла.
- **Анимации — по событиям `moved`:** очередь сегментов на игрока, боты ждут окончания анимаций.
- Тени PCF 1024², `dpr` ограничен 2 — компромисс для мобильных.

## Адаптивность
- Сетка «сцена | панель» на горизонтальном экране; при ширине < 900px или портретной ориентации — «сцена сверху, панель снизу». `100dvh`, `safe-area-inset` под вырезы телефонов, кнопки ≥ 40px, `touch-action: none` на canvas, события указателя (а не мыши).

## Инструменты
- TypeScript strict + `noUncheckedIndexedAccess`. Vitest для движка/ботов, Playwright-смоук. Сборка с `base: './'` для открытия из WebView/file://.
- Версия `@playwright/test` закреплена под предустановленный Chromium окружения (1.63). Путь к браузеру можно переопределить `PW_CHROMIUM_PATH`.
