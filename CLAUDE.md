## Что это за проект
Онлайн-настольная party-игра на четверых (рабочее имя сборки **Party Board**, первая карта **«Мегаполис»**): экономика как в классической настольной игре + 2 мини-игры, дуэли за сделки, 3 предмета, призрак после банкротства. Сервер авторитетный. Один web-клиент для ПК, телефона (строго вертикально) и будущих приложений Android/iOS через Capacitor.

**Юридическое ограничение:** никаких «Monopoly», Hasbro, оригинальных названий улиц, текстов карточек, оформления, фигурок, чужих марок и ассетов. Всё содержимое — собственное.

## Технологии (фактически установлено)
- Node.js ≥ 22.13 (в облачной среде проверено на 22.22), npm workspaces, один `package-lock.json`.
- TypeScript 7 (`strict`, `noUncheckedIndexedAccess`), один корневой `tsconfig.json` на весь монорепозиторий.
- Клиент: React 19, Vite 8, three 0.186, @react-three/fiber 9, @react-three/drei 10, Zustand 5, socket.io-client 4, шрифт `@fontsource/rubik`.
- Сервер: socket.io 4, встроенный `node:sqlite` (без нативных модулей), zod 4 (схемы в `packages/protocol`), tsx (dev), esbuild (сборка).
- Тесты: Vitest 5 (ядро, сервер, раскладка), Playwright 1.63 (E2E; версия закреплена под браузер облачной среды).
- Мобильная оболочка: Capacitor (конфигурация `apps/client/capacitor.config.json`; нативные проекты ещё не сгенерированы — см. PROGRESS.md).

## Основные системы
- **Ядро правил** (`game-core/engine.ts`): фазы `PRE_ROLL → [PURCHASE|AUCTION|RENT_CHOICE|DEBT] → POST_ROLL`, вставки `TRADE`, `DUEL_OFFER`, `DUEL`, граница раунда → `MINIGAME`, конец → `FINISHED`. Все дедлайны — абсолютное серверное время в состоянии.
- **Мини-игры** (`game-core/minigames.ts`): «Касса закрывается» (реакция) и «Курьер без навигатора» (память); один модуль для общей игры и для дуэли. Клиент шлёт только нажатия, очки считает сервер.
- **Сервер** (`apps/server/src/rooms.ts`): гость = UUID + секрет (SHA-256 в БД); комната с кодом; 4 места `s0…s3`; команды с `commandId` (идемпотентность); запись в SQLite **до** ответа и рассылки; один таймер на комнату по `nextDeadline`; пауза пустой комнаты; восстановление после рестарта; вытеснение старой сессии.
- **Клиент**: ортокамера почти сверху; профили раскладки `landscape`/`portrait` (одни индексы клеток); DOM-плашки привязаны к точкам поля (`render/BoardAnchor.tsx`); анимации — только из свежих событий снимка.

## Правила разработки
- **Правила живут только в `packages/game-core`.** Сервер — единственный авторитет. Клиент импортирует ядро только для чтения/подписей, не меняет состояние и не дублирует проверки.
- **Не смешивай каноническое состояние с UI и анимацией.** Сервер не ждёт клиентов; отставший клиент восстанавливается по снимку.
- В `game-core` нет `Date.now()` и `Math.random()`: время — параметр `now`, случайность — `ctx.rng` (состояние ГСЧ хранится в матче).
- Все числа правил — в `packages/content/src/ruleset.ts` и данных карты, не в обработчиках. После изменения — обновить `docs/RULES_V1.md`, тесты и подсказки UI.
- Новая команда = тип в `game-core/types.ts` + zod-схема в `protocol` + обработчик + тест (ядро и/или сервер).
- Публичные снимки (`views.ts`) не должны содержать `rng`, `seed`, порядок колоды, скрытые ответы мини-игр, секреты сессий.
- Канонические ID и порядок 32 клеток одинаковы на всех клиентах; профили раскладки меняют только координаты. Не смешивать правила 32 и 40 клеток.
- Dev-инструменты (`dev:cheat`, боты на пустых местах) — только при `PB_DEV=1`; в production сервер их отклоняет. Скриншоты, полученные через них, помечать как таковые.
- Все пользовательские тексты — на русском. Код и комментарии — можно по-английски.
- Графику менять через `apps/client/public/assets.json` (см. `docs/ASSETS.md`), а не правкой кода, если это возможно.
- **Не правь файлы клиента во время `npm run e2e`**: Vite перезагрузит страницы и сломает прогон.
- В облачной среде не убивай процессы по шаблону `pkill -f …`: шаблон совпадает с командной строкой самого инструмента и обрывает его. Останавливай по PID или через фоновые задачи.

## Проверки перед коммитом
```
npm run typecheck
npm test            # Vitest: ядро, сервер (4 Socket.IO-клиента, рестарт из SQLite, партия до финала), раскладка
npm run e2e         # Playwright, долго (4 WebGL-контекста); пишет docs/screenshots/
```
Не выдавай эмуляцию размеров браузера за проверку на телефоне, а dev-сокращения — за честную партию. Записывай факты в `docs/VALIDATION.md`.
